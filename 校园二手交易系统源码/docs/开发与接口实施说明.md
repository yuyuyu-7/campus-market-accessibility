# 开发与接口实施说明

## 结构和依赖

使用.NET 8，Windows WPF桌面界面，本机ASP.NET Core服务和SQLite数据库。

`Campus.Desktop → Campus.Server → Campus.Core`为工程引用关系。桌面项目只负责表单、导航和HTTP客户端，服务层负责身份、图片、商品与交易规则，Core定义实体、通用存储端口和`IProductForTrade`。商品交易互操作通过窄接口完成，并使用同一连接和事务。数据访问隐藏在`Database`实现中，业务服务不直接拼接SQL。

数据库每种实体独立建表，行内用JSON保存实体，账号有唯一索引。事务由单进程串行锁与SQLite事务共同保护。

## 从源码构建

在Windows x64上安装.NET 8 SDK，进入src目录：

```powershell
dotnet build CampusMarket.sln -c Release
dotnet run --project Campus.Desktop/Campus.Desktop.csproj
dotnet publish Campus.Desktop/Campus.Desktop.csproj -c Release -r win-x64 --self-contained true -o ../app
```

首次构建需要从NuGet下载Microsoft.Data.Sqlite 8.0.11及其依赖。交付的app目录已经完成发布，不需要运行这些命令。交付运行库为.NET 8.0.33。

## 数据与启动参数

正式程序默认数据目录为`%LOCALAPPDATA%\CampusMarketCourse\campus.db`；演示启动脚本使用包内`demo\campus.db`。SQLite采用WAL日志，备份运行中的库时应使用SQLite备份API，不能只复制主文件而遗漏WAL。

```powershell
app/CampusMarket.exe --server --db "独立测试数据库的绝对路径" --port 5079
python tests/integration.py http://127.0.0.1:5079 result.json
python tests/performance_smoke.py http://127.0.0.1:5079 perf.json
```

`--server`用于HTTP测试，不打开窗口，测试后需结束该测试进程。`--port`默认5078，只绑定127.0.0.1。正式主窗口关闭时会停止同进程服务。

`tests/Campus.UiHarness`是单独的测试工程。它通过真实接口创建虚构用户，构造与正式程序相同的MainWindow并记录UIA、焦点、按键及渲染截图。正式程序不引用此测试工程，没有免鉴权入口。界面测试曾使用该启动器建立测试会话，不能据此声称手动输入账号密码的完整流程已经被自动执行。

## 接口契约与自审记录

原设计契约保留于同目录的`原设计接口契约.json`。单人开发同时承担客户端、服务端和测试责任，实施前在此记录响应字段的兼容处理并统一更新客户端和测试，未改变原契约的方法、路径、输入字段及权限规则。

| 接口 | 实施响应与兼容处理 |
|---|---|
| 注册 | 保留userId，同时增加id、account、nickname、contact、version，供当前客户端使用 |
| 登录 | 保留token、expiresIn，同时返回当前用户资料user |
| 退出 | 返回revoked=true，同时返回loggedOut=true |
| 图片上传 | 返回imageId、sizeBytes和mimeType |
| 商品写入 | 返回含id、status、version的完整商品投影；不返回公开联系方式 |
| 交易操作 | 返回含原字段的完整交易投影，附当前productVersion和productStatus |
| 通用错误 | code、message、data=null、requestId和errors数组；本实现使用单条message，errors为空数组 |
| 探测 | /ready执行独立Probe表的写、读和回滚；/health用于进程存活信息 |

匿名注册和登录需要X-Client-Id；所有写请求需要Idempotency-Key。相同主体、路径和键30秒内重复提交被409拒绝，异体同键被409拒绝。这里按请求体原始字节摘要比较，不将不同JSON排版自动归并为同一请求体。重复请求不会再次写业务；当前不附首次resourceId，须通过列表或详情确认首次结果。

未来若移除或重命名既有字段、改变状态语义，必须先记录客户端、服务端和测试的共同审查结果，再升级契约版本。此次无障碍适配前后的服务端源码哈希一致。
